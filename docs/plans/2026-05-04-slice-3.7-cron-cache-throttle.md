# Slice 3.7 — Cron Tasks + Redis Cache Wiring + Throttler Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (in the executing session) to implement this plan task-by-task. Dispatch a fresh subagent per task; review between tasks; halt on failure. **This is a plumbing slice — three independent infrastructure concerns bundled into one execution window.** No new user-visible features. The deliverable is "the system now self-maintains (cron), uses production-grade Redis caching, and rate-limits the endpoints that need it." Pace per concern: cache swap → throttler wiring → cron services. Each is independently shippable; the slice is done when all three are wired.

**Goal:** Three things, each load-bearing for a production-grade system:

1. **Swap the in-memory cache to Redis store.** Today `CacheModule.register({ isGlobal: true, ttl: 60_000 })` uses an in-process Map (per Slice 1.x setup). Cache invalidations don't propagate across restarts; cached aggregations re-warm cold every backend boot. Wire `cache-manager-redis-yet` so `@nestjs/cache-manager` writes to the same Redis container BullMQ uses. Existing call sites (`JobsService.listPublic`, `AdminAnalyticsService.overview`, `AdminBiasMonitorService.overview`) keep working unchanged — the swap is transparent at the consumer level.

2. **Wire `@nestjs/throttler` with Redis storage.** Apply rate limits to: auth endpoints (5 req/60s per IP — protects against brute force on login + register + password reset), match score recompute via 2.6's path (1 req/60s per user — replaces 2.5's manual rate-limit check that I documented at the time as a "Throttler not registered yet" workaround), resume upload (5 req/hour per user — protects against accidental upload-storm + AI cost overrun). Throttler responses surface as HTTP 429 with the existing `HttpExceptionFilter` carrying retry-after metadata.

3. **Ship `CronModule` with three scheduled tasks.** Register `@nestjs/schedule` and create three cron services:
   - `expireOffersHourly` — every hour at minute 0, find offers with `status='pending' AND expires_at < now()`, set `status='expired'`. Notify candidate via email.
   - `archivePastDeadlineJobs` — daily at midnight, find jobs with `status='published' AND application_deadline < now()`, set `status='archived'`. Invalidate public job cache.
   - `cleanupUnverifiedAccounts` — weekly Sunday 02:00 UTC, find auth users with `email_confirmed_at IS NULL AND created_at < now() - 7d`, delete via `SupabaseAdminService.deleteUser` (cascades to profiles via FK).

Plus housekeeping: create `apps/api/.env.example` documenting all required env vars (REDIS_URL, OPENAI_API_KEY, SUPABASE_*, SMTP_*, etc.) so a fresh checkout has a copy-paste reference.

**Architecture:** All three concerns live in `apps/api/src/`. Cache swap is one config change in `app.module.ts`. Throttler is `ThrottlerModule.forRootAsync` in `app.module.ts` + `@Throttle` decorators on three controllers (auth + scoring + resumes). Cron is a new `apps/api/src/cron/` directory with `cron.module.ts` registering `ScheduleModule.forRoot()` + three sibling services each owning one cron, every cron writes to `audit_logs` with execution metadata. **No new endpoints.** Frontend completely untouched. The slice is purely backend-infrastructure work.

**Tech Stack (per `docs/main/tech-stack.md` line 27-30 + 143-154):**
- `@nestjs/schedule` — cron decorators (`@Cron`, `CronExpression.*`)

- `cache-manager-redis-yet` ^5 + existing `@nestjs/cache-manager` — Redis store adapter

## Notes from prior slices' execution (read before starting)

- **Hook naming:** if the dev-only debug endpoint ships, orval emits `useAdminCronControllerRunV1`. Otherwise no codegen surface in this slice.
- **OpenAI SDK v6.35:** zero AI calls in this slice.
- **`HttpExceptionFilter` preserves extra fields** (2.7 fix). Throttler 429 responses include `retryAfter` in the body — the filter shouldn't strip it.
- **`@nestjs/throttler` v6 + Redis storage:** check whether v6 includes `ThrottlerStorageRedisService` natively or whether `nestjs-throttler-storage-redis` is the correct adapter package. Pinning matters — the executor should `pnpm view @nestjs/throttler` to see version compatibility.
- **`@nestjs/schedule` decorator semantics:** `@Cron('0 * * * *')` runs at minute 0 of every hour; `@Cron(CronExpression.EVERY_DAY_AT_MIDNIGHT)` runs at 00:00 server time. **Sprint behavior:** the backend runs in the dev container's timezone (UTC by default); production should also run in UTC. Document if the timezone seems off.
- **`@Cron` jobs do not stack** — if the previous run is still executing when the next tick fires, `@nestjs/schedule` queues it. For sprint, all crons are fast (<5s); not a concern.
- **`SupabaseAdminService.deleteUser`** exists (1.4) and is used in 3.1's user delete. Cleanup cron reuses the same method.
- **The manual rate-limit in ScoringService.computeProfileScore (Slice 2.5)** — the comment says "use Throttler when registered." 3.7 registers it. **Decision (per Task 6):** keep the manual check AS WELL — defense in depth. Throttler protects per-IP; the manual check is per-user. Both are valuable. Document this dual-layer in the slice's commit message.
- **Cache store swap is the riskiest change.** All five cache call sites must keep working. The cache-manager-redis-yet adapter wraps ioredis; the `@Inject(CACHE_MANAGER)` interface stays identical. If a call site breaks, it'll be a serialization issue (Redis stores strings; complex objects need JSON.stringify/parse — adapter handles this automatically).
- **Throttler + WebSockets:** the project doesn't use WebSockets, so the standard HTTP throttle works. Skip Socket.IO concerns.
- **Cron services should NOT use `@nestjs/bullmq`** for sprint scope — they run inline in the scheduler thread. If a cron grows past 30 seconds, refactor it to enqueue a BullMQ job (use 3.6's pattern). For sprint, all 3 are sub-second operations.

## Phase B — Cache: Swap to Redis Store (Task 3)

### Task 3: Modify `app.module.ts` to use Redis cache store

**Files:**
- Modify: `apps/api/src/app.module.ts`

**Step 1:** Replace the `CacheModule.register({ isGlobal: true, ttl: 60_000 })` line with the async Redis-store version. Add imports.

```ts
// Top of file: add imports
import { CacheModule } from "@nestjs/cache-manager";
import { ConfigModule, ConfigService } from "@nestjs/config";
import { redisStore } from "cache-manager-redis-yet";

// In @Module imports, replace:
//   CacheModule.register({ isGlobal: true, ttl: 60_000 }),
// With:
CacheModule.registerAsync({
  isGlobal: true,
  imports: [ConfigModule],
  inject: [ConfigService],
  useFactory: async (config: ConfigService) => {
    const url = config.get<string>("REDIS_URL") ?? "redis://localhost:6379";
    try {
      const store = await redisStore({
        url,
        // Default TTL on cache.set if caller doesn't pass one — match the prior 60s default
        ttl: 60_000,
      });
      const logger = new Logger("CacheModule");
      logger.log(`CacheModule: connected to Redis at ${url}`);
      return { store, ttl: 60_000 };
    } catch (err) {
      const logger = new Logger("CacheModule");
      logger.warn(
        `CacheModule: Redis unreachable at ${url} (${(err as Error).message}); falling back to in-memory store. Cached aggregations will not survive restarts.`,
      );
      // Default in-memory store if Redis is down (graceful degradation per plan rules)
      return { ttl: 60_000 };
    }
  },
}),
```

**Note on the `Logger` import:** add `import { Logger } from "@nestjs/common";` if not already present at the top.

**Step 2:** Verify all existing cache call sites — they should continue working because they all use `@Inject(CACHE_MANAGER)` + `cache.get(key)` / `cache.set(key, value, ttlMs)`. The Redis store adapter handles JSON (de)serialization transparently. No code changes needed in:

```ts
import { Inject, Injectable, Logger } from "@nestjs/common";
import { Cron, CronExpression } from "@nestjs/schedule";
import { and, eq, lt, sql } from "drizzle-orm";
import { offersTable, profilesTable, applicationsTable, jobsTable } from "@aurahire/db";

import { AuditService } from "../audit";
import { DRIZZLE_CLIENT, type DrizzleClient } from "../db/db.module";
import { EmailService } from "../email/email.service";

const CRON_NAME = "expire-offers";

@Injectable()
export class ExpireOffersCron {
  private readonly logger = new Logger(ExpireOffersCron.name);

  constructor(
    @Inject(DRIZZLE_CLIENT) private readonly db: DrizzleClient,
    private readonly audit: AuditService,
    private readonly email: EmailService,
  ) {}

  @Cron("0 * * * *", { name: CRON_NAME })
  async run(): Promise<{ affectedRows: number; durationMs: number }> {
    return this.execute();
  }

  /** Public for the dev-only debug endpoint to invoke manually. */
  async execute(): Promise<{ affectedRows: number; durationMs: number }> {
    const startedAt = Date.now();

    try {
      // Find expired pending offers
      const candidates = await this.db
        .select({
          offerId: offersTable.id,
          applicationId: offersTable.applicationId,
          title: offersTable.title,
          candidateId: applicationsTable.candidateId,
          candidateEmail: profilesTable.email,
          candidateName: profilesTable.fullName,
          jobTitle: jobsTable.title,
        })
        .from(offersTable)
        .innerJoin(applicationsTable, eq(applicationsTable.id, offersTable.applicationId))
        .innerJoin(profilesTable, eq(profilesTable.id, applicationsTable.candidateId))
        .innerJoin(jobsTable, eq(jobsTable.id, applicationsTable.jobId))
        .where(
          and(
            eq(offersTable.status, "pending"),
            lt(offersTable.expiresAt, new Date()),
          ),
        );

      if (candidates.length === 0) {
        this.logger.log(`[${CRON_NAME}] no expired offers`);
        await this.audit.log({
          actorId: null,
          actorType: "system",
          action: `cron.${CRON_NAME.replace(/-/g, "_")}.executed`,
          entityType: "cron",
          entityId: "00000000-0000-0000-0000-000000000000", // sentinel for cron entries
          details: { affectedRows: 0, durationMs: Date.now() - startedAt },
        });
        return { affectedRows: 0, durationMs: Date.now() - startedAt };
      }

      // Update + email per offer
      const offerIds = candidates.map((c) => c.offerId);
      await this.db
        .update(offersTable)
        .set({ status: "expired", updatedAt: new Date() })
        .where(sql`${offersTable.id} = ANY(${offerIds}::uuid[])`);

      // Per-offer audit + email (best-effort; one failure doesn't fail the cron)
      for (const c of candidates) {
        try {
          await this.audit.log({
            actorId: null,
            actorType: "system",
            action: "offer.expired",
            entityType: "offer",
            entityId: c.offerId,
            details: {
              applicationId: c.applicationId,
              candidateId: c.candidateId,
              jobTitle: c.jobTitle,
            },
          });

          // Send expiry email — sprint-acceptable to use a plain string template if no React Email exists
          await this.email.send({
            to: c.candidateEmail,
            subject: `Your offer for ${c.jobTitle} has expired`,
            text: `Hi ${c.candidateName},\n\nYour offer for "${c.jobTitle}" has expired. If you'd like to discuss, please contact the recruiter.\n\n— AuraHire`,
          });
        } catch (innerErr) {
          this.logger.warn(`[${CRON_NAME}] post-expire side effect failed for offer ${c.offerId}: ${(innerErr as Error).message}`);
        }
      }

      const durationMs = Date.now() - startedAt;
      await this.audit.log({
        actorId: null,
        actorType: "system",
        action: `cron.${CRON_NAME.replace(/-/g, "_")}.executed`,
        entityType: "cron",
        entityId: "00000000-0000-0000-0000-000000000000",
        details: { affectedRows: candidates.length, durationMs },
      });

      this.logger.log(`[${CRON_NAME}] expired ${candidates.length} offer(s) in ${durationMs}ms`);
      return { affectedRows: candidates.length, durationMs };
    } catch (err) {
      this.logger.error(`[${CRON_NAME}] failed: ${(err as Error).message}`);
      throw err;
    }
  }
}
```

```ts
import { Inject, Injectable, Logger } from "@nestjs/common";
import { Cron, CronExpression } from "@nestjs/schedule";
import { and, eq, lt, sql } from "drizzle-orm";
import { jobsTable } from "@aurahire/db";

import { AuditService } from "../audit";
import { DRIZZLE_CLIENT, type DrizzleClient } from "../db/db.module";

const CRON_NAME = "archive-past-deadline-jobs";

@Injectable()
export class ArchivePastDeadlineJobsCron {
  private readonly logger = new Logger(ArchivePastDeadlineJobsCron.name);

  constructor(
    @Inject(DRIZZLE_CLIENT) private readonly db: DrizzleClient,
    private readonly audit: AuditService,
  ) {}

  @Cron(CronExpression.EVERY_DAY_AT_MIDNIGHT, { name: CRON_NAME })
  async run(): Promise<{ affectedRows: number; durationMs: number }> {
    return this.execute();
  }

  async execute(): Promise<{ affectedRows: number; durationMs: number }> {
    const startedAt = Date.now();

    try {
      const today = new Date();
      today.setHours(0, 0, 0, 0);

      // Find published jobs past their application_deadline
      const candidates = await this.db
        .select({ id: jobsTable.id, title: jobsTable.title, recruiterId: jobsTable.recruiterId })
        .from(jobsTable)
        .where(
          and(
            eq(jobsTable.status, "published"),
            sql`${jobsTable.applicationDeadline} IS NOT NULL`,
            lt(jobsTable.applicationDeadline, today),
          ),
        );

      if (candidates.length === 0) {
        const durationMs = Date.now() - startedAt;
        this.logger.log(`[${CRON_NAME}] nothing to archive`);
        await this.audit.log({
          actorId: null,
          actorType: "system",
          action: `cron.archive_past_deadline_jobs.executed`,
          entityType: "cron",
          entityId: "00000000-0000-0000-0000-000000000000",
          details: { affectedRows: 0, durationMs },
        });
        return { affectedRows: 0, durationMs };
      }

      const ids = candidates.map((c) => c.id);
      await this.db
        .update(jobsTable)
        .set({ status: "archived", updatedAt: new Date() })
        .where(sql`${jobsTable.id} = ANY(${ids}::uuid[])`);

      // Per-job audit
      for (const c of candidates) {
        await this.audit.log({
          actorId: null,
          actorType: "system",
          action: "job.archived_by_cron",
          entityType: "job",
          entityId: c.id,
          details: { title: c.title, recruiterId: c.recruiterId },
        });
      }

      const durationMs = Date.now() - startedAt;
      await this.audit.log({
        actorId: null,
        actorType: "system",
        action: `cron.archive_past_deadline_jobs.executed`,
        entityType: "cron",
        entityId: "00000000-0000-0000-0000-000000000000",
        details: { affectedRows: candidates.length, durationMs },
      });

      this.logger.log(`[${CRON_NAME}] archived ${candidates.length} job(s) in ${durationMs}ms`);
      return { affectedRows: candidates.length, durationMs };
    } catch (err) {
      this.logger.error(`[${CRON_NAME}] failed: ${(err as Error).message}`);
      throw err;
    }
  }
}
```

```ts
import { Inject, Injectable, Logger } from "@nestjs/common";
import { Cron } from "@nestjs/schedule";
import { and, eq, isNull, lt } from "drizzle-orm";
import { profilesTable } from "@aurahire/db";

import { AuditService } from "../audit";
import { DRIZZLE_CLIENT, type DrizzleClient } from "../db/db.module";
import { SupabaseAdminService } from "../lib/supabase-admin";

const CRON_NAME = "cleanup-unverified-accounts";

@Injectable()
export class CleanupUnverifiedAccountsCron {
  private readonly logger = new Logger(CleanupUnverifiedAccountsCron.name);

  constructor(
    @Inject(DRIZZLE_CLIENT) private readonly db: DrizzleClient,
    private readonly audit: AuditService,
    private readonly supabaseAdmin: SupabaseAdminService,
  ) {}

  // Sundays 02:00 UTC
  @Cron("0 2 * * 0", { name: CRON_NAME })
  async run(): Promise<{ affectedRows: number; durationMs: number }> {
    return this.execute();
  }

  async execute(): Promise<{ affectedRows: number; durationMs: number }> {
    const startedAt = Date.now();

    try {
      const sevenDaysAgo = new Date(Date.now() - 7 * 24 * 60 * 60 * 1000);

      // Sprint-acceptable approach: query Supabase auth.users via the admin client
      // for unconfirmed-email rows older than 7 days. Implementation depends on
      // SupabaseAdminService.listUsers signature.
      //
      // Alternative (if the admin listing is paginated and slow): query profiles
      // where status='active' AND last_login_at IS NULL AND created_at < 7d
      // (proxy for "never logged in" — close enough for sprint).
      const { users } = await this.supabaseAdmin.listUsers({ page: 1, perPage: 200 });

      const candidates = users.filter(
        (u) =>
          (u as { email_confirmed_at?: string | null }).email_confirmed_at == null &&
          new Date(u.created_at) < sevenDaysAgo,
      );

      if (candidates.length === 0) {
        const durationMs = Date.now() - startedAt;
        this.logger.log(`[${CRON_NAME}] no unverified accounts to clean up`);
        await this.audit.log({
          actorId: null,
          actorType: "system",
          action: `cron.cleanup_unverified_accounts.executed`,
          entityType: "cron",
          entityId: "00000000-0000-0000-0000-000000000000",
          details: { affectedRows: 0, durationMs },
        });
        return { affectedRows: 0, durationMs };
      }

      let deletedCount = 0;
      for (const u of candidates) {
        try {
          await this.supabaseAdmin.deleteUser(u.id);
          // Profile cascades via FK; no explicit profile delete needed
          await this.audit.log({
            actorId: null,
            actorType: "system",
            action: "user.deleted_unverified_cleanup",
            entityType: "profile",
            entityId: u.id,
            details: { email: u.email, reason: "unverified > 7 days" },
          });
          deletedCount++;
        } catch (innerErr) {
          this.logger.warn(`[${CRON_NAME}] delete failed for user ${u.id}: ${(innerErr as Error).message}`);
        }
      }

      const durationMs = Date.now() - startedAt;
      await this.audit.log({
        actorId: null,
        actorType: "system",
        action: `cron.cleanup_unverified_accounts.executed`,
        entityType: "cron",
        entityId: "00000000-0000-0000-0000-000000000000",
        details: { affectedRows: deletedCount, durationMs },
      });

      this.logger.log(`[${CRON_NAME}] deleted ${deletedCount} unverified user(s) in ${durationMs}ms`);
      return { affectedRows: deletedCount, durationMs };
    } catch (err) {
      this.logger.error(`[${CRON_NAME}] failed: ${(err as Error).message}`);
      throw err;
    }
  }
}
```

```ts
import {
  Controller,
  ForbiddenException,
  HttpCode,
  HttpStatus,
  NotFoundException,
  Param,
  Post,
} from "@nestjs/common";
import { ApiBearerAuth, ApiOperation, ApiResponse, ApiTags } from "@nestjs/swagger";

import { Roles } from "../common/decorators/roles.decorator";

import { ExpireOffersCron } from "./expire-offers.cron";
import { ArchivePastDeadlineJobsCron } from "./archive-past-deadline-jobs.cron";
import { CleanupUnverifiedAccountsCron } from "./cleanup-unverified-accounts.cron";

@ApiTags("admin-cron-debug")
@ApiBearerAuth()
@Controller("admin/cron")
export class CronAdminController {
  constructor(
    private readonly expireOffers: ExpireOffersCron,
    private readonly archiveJobs: ArchivePastDeadlineJobsCron,
    private readonly cleanupUnverified: CleanupUnverifiedAccountsCron,
  ) {}

  @Post("run/:cronName")
  @Roles("admin")
  @HttpCode(HttpStatus.OK)
  @ApiOperation({
    summary:
      "DEV ONLY: manually trigger a named cron service so the human can verify behavior without waiting for the schedule. Disabled in production.",
  })
  @ApiResponse({ status: 200 })
  @ApiResponse({ status: 403, description: "Disabled in production" })
  @ApiResponse({ status: 404, description: "Unknown cron name" })
  async run(@Param("cronName") cronName: string): Promise<{ data: { affectedRows: number; durationMs: number } }> {
    if (process.env.NODE_ENV === "production") {
      throw new ForbiddenException({
        code: "DISABLED_IN_PROD",
        message: "Manual cron triggers are disabled in production",
      });
    }

    let result: { affectedRows: number; durationMs: number };
    switch (cronName) {
      case "expire-offers":
        result = await this.expireOffers.execute();
        break;
      case "archive-jobs":
      case "archive-past-deadline-jobs":
        result = await this.archiveJobs.execute();
        break;
      case "cleanup-unverified":
      case "cleanup-unverified-accounts":
        result = await this.cleanupUnverified.execute();
        break;
      default:
        throw new NotFoundException({
          code: "UNKNOWN_CRON",
          message: `Unknown cron name: ${cronName}`,
          available: ["expire-offers", "archive-jobs", "cleanup-unverified"],
        });
    }

    return { data: result };
  }
}
```

## Why This Slice Matters

Three reasons, each unsexy but load-bearing:

1. **Cache becomes durable.** Until this slice, every backend restart cleared the analytics cache, the bias-monitor cache, the public job cache. First admin to refresh after a restart paid the full 5-minute aggregation cost. After this slice, the cache lives in Redis, survives restarts, and could (in production) be shared across multiple backend instances. The user-visible difference is "admin dashboards feel snappy after deploys." The thesis-defending difference is "this is what production caching looks like."

2. **Throttler closes the brute-force surface.** Until this slice, an attacker could hammer `/auth/login` as fast as the backend could respond. After this slice, 5 attempts in 60 seconds and they're 429'd. Same protection on profile recompute (1/min/user — protects OpenAI cost from accidental keyboard-stuck spam), resume upload (5/hour — protects storage + parse cost). Defense in depth: per-IP throttle catches anonymous brute force, per-user manual checks (where they exist from 2.5) catch authenticated abuse.

3. **Cron makes the system self-maintain.** Three sources of accumulated debt without crons: (a) offers stuck in 'pending' forever after the candidate ghosts past `expires_at` — recruiter has to manually expire each one; (b) archived jobs that should be hidden from public browse stay published past their deadline; (c) unverified-email accounts pile up in `auth.users` indefinitely. Three crons, three accumulated debts paid down automatically. The thesis-defending phrase is "the system maintains itself" — three concrete examples to point to.

The 60-minute budget is real. The risk is the cache swap (Phase B) silently breaking a downstream service — the verification step "refresh the analytics page after the swap and check Redis CLI for keys" is the gate that catches it. After 3.7, only 3.8 (Day 3 final polish + interview/offer feature surfaces) remains before Day 4 deployment work.
