# Slice 4.3 — End-to-End Demo Path Verification Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans`. This slice has **NO code changes**. The agent's job is to walk through the demo script with the human, capture failures as discrete tickets, and curate the punch list. Every "step fails" outcome becomes a ticket; every "step works" outcome moves the slice forward. **Treat this as a structured QA pass, not a bug-fixing session** — fixes go in Slice 4.5 buffer.

**Goal:** Walk the **complete thesis demo path** end-to-end against the deployed production system (Vercel frontend + Railway backend + production Supabase + production Redis + Resend email). Every step in the script either passes (✓) or fails (with a ticket filed). Outcome: a punch list of items for Slice 4.5 to fix, ranked by demo-blocking severity.

**Architecture:** No code. The agent + human pair on a shared screen, walking the 30-step script below. The agent records observations to a new file `docs/plans/2026-05-05-slice-4.3-demo-verification-results.md` as steps complete.

**Sprint reference:** `docs/main/sprint-plan.md` § Day 4 → Slice 4.3
**Estimated wall time:** 45 min walking the script + 15 min triaging the punch list
**Depends on:** 4.1 + 4.2 deployed; production DB seeded with admin + recruiter + 18 jobs.

## Phase A — The 30-step demo script

Walk these in order. **Do not fix anything mid-script** — record + move on.

### Phase A.1 — Public surfaces (steps 1-3)

1. **Marketing landing**: visit `https://<vercel-url>` → loads cleanly, no console errors
2. **Public jobs browse**: `/jobs` → 18 TechCorp jobs visible
3. **Public job detail**: click any job → full description renders; "Sign in to apply" CTA visible

### Phase A.2 — Auth (steps 4-6)

4. **Sign in (admin)**: `admin@admin.com / password123` → lands on `/admin`
5. **Sign out + sign in (recruiter)**: `maya@techcorp.dev / password123` → lands on `/recruiter`
6. **Register a candidate**: new email → onboarding wizard launches

### Phase A.3 — Candidate flow (steps 7-12)

7. **Onboarding step 1**: upload a real PDF resume → AI Shimmer plays → resume parses → step 2 prefilled with `<AiSuggestedBadge>` markers
8. **Complete onboarding** through step 5
9. **Compute Profile Score**: `/candidate` dashboard → "Compute" → 10s shimmer → ScoreRing + breakdown + evidence + Fairness disclosure
10. **Browse jobs as candidate**: `/candidate/jobs` → 18 jobs visible with match score column (lazy-computed or scored on apply)
11. **Apply to a job**: click any → resume picker + cover letter → Submit → 15s AI Shimmer → land on `/candidate/applications/[id]` with full ScoreRing + 4-component breakdown
12. **Verify email**: check Resend dashboard or recipient inbox → recruiter received "New application" email

### Phase A.4 — Recruiter flow (steps 13-19)

13. **Recruiter sees application**: as Maya, visit `/recruiter/jobs/[id]/applications` → candidate row visible, sorted by best-match
14. **Open application detail**: click → full review with score + evidence + cover letter + status actions
15. **Move to Screening**: click → status updates → candidate gets email
16. **Add recruiter notes**: type → Save → PATCH succeeds
17. **Schedule interview**: modal → fill form → Submit → candidate gets "Interview scheduled" email
18. **Send offer**: link → wizard → fill salary + start + benefits → Submit → candidate gets "Offer extended" email
19. **(Switch to candidate)**: visit `/candidate/applications/[id]` → Offer section visible with Accept/Decline buttons

### Phase A.5 — Hire arc completion (steps 20-22)

20. **Accept offer**: candidate clicks Accept → confirm → POST succeeds
21. **Application auto-advances**: status → 'hired'; recruiter receives "Offer accepted" email
22. **Audit trail intact**: as admin, `/admin/audit?action=offer.accepted` → entry visible

### Phase A.6 — Bias detection (steps 23-25)

23. **Recruiter creates biased job**: as Maya, `/recruiter/jobs/new` → write description with "rockstar engineer who is young and energetic" → Save Draft → Publish
24. **422 BIAS_CHECK_REQUIRED**: modal opens with 3 flagged terms
25. **Override + publish**: each flag with ≥10 char reason → modal auto-retries publish → job goes live

### Phase A.7 — Admin oversight (steps 26-30)

26. **Admin Command Center**: `/admin` → KPI tiles populated with real numbers
27. **AI Config + Preview Impact**: `/admin/ai-config` → change skills weight 40→50 → Preview Impact → see distribution shift → Save
28. **Apply weights to existing**: click "Apply weights to existing scores" → progress bar advances → completion toast → DB has 2 match_scores rows for the test application
29. **Bias Monitor**: `/admin/bias-monitor` → 3 overrides visible in Recent Override Decisions list with the recruiter's reasons from step 25
30. **Audit log + CSV export**: `/admin/audit` → filter by `score.match.computed` → export CSV → file downloads cleanly

## Phase B — Triage (Tasks 1–2)

### Task 1: Categorize every ✗

For each failed step in the results file:
- **BLOCKER**: cannot proceed past this step in the demo (e.g., apply submit returns 500)
- **MAJOR**: demo continues but the failure is visibly bad (e.g., Score Distribution chart is blank when it should have data)
- **MINOR**: cosmetic or edge-case (e.g., truncation looks awkward at exactly 320px viewport)

### Task 2: Build the 4.5 fix list

In the results file, write the prioritized punch list. Pass it to Slice 4.5's executor.
