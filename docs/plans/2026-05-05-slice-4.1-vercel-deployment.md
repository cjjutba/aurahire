# Slice 4.1 — Frontend Deployment (Vercel) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` (in the executing session) to walk this plan top-to-bottom. Most steps are commands the HUMAN runs in their own terminal or clicks in the Vercel dashboard — the executing agent's job is to write the config files (vercel.json, next config tweaks if needed), update env-setup docs, and verify type-check + build succeed locally before the human deploys. **The agent never runs `vercel deploy` per CLAUDE.md hard rule 3.**

**Goal:** Deploy `apps/web` (Next.js 16 frontend) to Vercel with all production env vars wired correctly. By end of this slice: `https://aurahire.vercel.app` (or chosen domain) loads the marketing landing page; sign-in/register flows work against the production Supabase project; the frontend talks to the production backend via `NEXT_PUBLIC_API_URL`. **Day 4.2 (Railway backend deploy) MUST be done first** — the frontend needs a backend URL to point at.

**Architecture:** Vercel hosts the Next.js 16 app from the monorepo root with `apps/web` as the project root. Build command runs Turborepo so workspace deps (`@aurahire/shared`, `@aurahire/db`) build first. Env vars are split into `NEXT_PUBLIC_*` (exposed to browser) and server-only (`SUPABASE_SERVICE_ROLE_KEY` is NEVER added here — it lives only in the backend Railway env per CLAUDE.md security rules).

## Phase A — Config files (Tasks 1–3)

### Task 1: Create `vercel.json` at repo root

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "buildCommand": "pnpm turbo run build --filter=@aurahire/web",
  "installCommand": "pnpm install --frozen-lockfile",
  "framework": "nextjs",
  "outputDirectory": "apps/web/.next",
  "ignoreCommand": "pnpm turbo-ignore @aurahire/web"
}
```

**Note:** Vercel's monorepo support detects `pnpm-workspace.yaml` automatically. The `ignoreCommand` skips redundant builds when only `apps/api` changed.

### Task 2: Create `apps/web/.env.production.example`

```bash
# Production env for apps/web — set these in Vercel dashboard, NOT committed.
NEXT_PUBLIC_API_URL=https://<railway-backend-domain>
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<public anon key — safe to expose>
NEXT_PUBLIC_APP_URL=https://<your-vercel-domain>
```

**Security check:** verify NO `SUPABASE_SERVICE_ROLE_KEY`, NO `OPENAI_API_KEY`, NO SMTP creds. Those live ONLY in Railway backend env per CLAUDE.md.

### Task 3: Extend `docs/main/env-setup.md` with "Production: Vercel" section

Document: Vercel project setup, root directory = `.`, build command, env var list, GitHub auto-deploy hookup, custom domain (optional).

## Phase B — Local validation before deploy (Task 4)

### Task 4: Verify production build works locally

```bash
# Agent runs (read-only build check):
pnpm turbo run build --filter=@aurahire/web
```

Expected: green build. Common failures:
- Missing env vars — Next.js fails build if any `process.env.NEXT_PUBLIC_*` referenced in code is undefined; either stub with placeholder or skip check
- Turborepo workspace resolution — verify `@aurahire/shared` builds first

If green, the human can confidently deploy.

## Phase C — Human deploys via Vercel dashboard (Tasks 5–7)

### Task 5: Create Vercel project (HUMAN ACTION)

1. Visit https://vercel.com/new
2. Import the GitHub repo
3. Set Root Directory = `.` (monorepo root)
4. Framework preset: Next.js (auto-detected)
5. Build settings should auto-fill from `vercel.json`

### Task 6: Add production env vars (HUMAN ACTION)

In Vercel dashboard → Settings → Environment Variables, add the 4 vars from `.env.production.example`. Set scope to **Production** only (not Preview/Development unless intentional).

### Task 7: First deploy (HUMAN ACTION)

Click "Deploy". Wait ~2-5 minutes. On success:
- Visit the assigned `*.vercel.app` URL
- Check the marketing landing renders
- Sign in as `admin@admin.com / password123` — verify auth works against production Supabase

If deploy fails: read the build log; common issues are missing env vars or Turborepo workspace dependency order.
