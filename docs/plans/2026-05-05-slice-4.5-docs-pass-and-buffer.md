# Slice 4.5 — Documentation Pass + Buffer Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`. This is **the last slice of the sprint.** Two concerns: (1) docs pass — every doc in `docs/main/` reflects the shipped reality, no stale references; (2) buffer — fix the punch-list items 4.3 surfaced as BLOCKER or MAJOR. **Resist scope creep** — the temptation here is to add features. The job is to leave the system shippable + defensible, not bigger.

**Goal:** Two outcomes:

1. **Docs are truthful** — every claim in `docs/main/*.md` matches the shipped code. Stale references get fixed; "Coming in a future slice" gets removed; the README + CLAUDE.md + AGENTS.md are accurate for someone forking the repo today.

2. **Punch list cleared** — every BLOCKER + MAJOR ticket from 4.3's verification gets a fix commit. MINOR tickets get triaged: in-scope → fix; out-of-scope → moved to a new `docs/post-sprint-backlog.md` for future iteration.

**Architecture:** Mostly editing existing docs + small targeted code fixes. No new modules, no new endpoints. Treat each punch-list ticket as an independent task; treat the docs pass as a checklist sweep.

**Sprint reference:** `docs/main/sprint-plan.md` § Day 4 → Slice 4.5
**Estimated wall time:** 90 min docs + N min per ticket (varies by punch list size)
**Depends on:** 4.3 verification complete with prioritized punch list; 4.4 cheat sheet in hand.

## Why This Slice Matters

Two reasons, both about the day after the sprint:

1. **Truthful docs are the system's interface.** A future contributor opens this repo and reads `docs/main/`. If those docs lie, they spend hours debugging assumptions that no longer hold. A sprint-quality docs pass — done in the same session as the code that contradicted them — is cheap insurance against that frustration.

2. **The punch list closes honest.** 4.3's verification found N items. Some were demo-blockers; some were cosmetic. Treating BLOCKER + MAJOR as "must close" and MINOR as "deliberately deferred with a doc trail" is more honest than "we'll fix it eventually" — which usually means never.

When this slice is done, the sprint is done. The system runs in production, the docs match the code, the punch list is either closed or explicitly tracked. Anything else is post-sprint work.
