````markdown
## Known Limitations (be honest)

- **No disparate-impact statistical tests** - by design. The system intentionally does not collect protected-class data (PII redaction). Documented in /admin/bias-monitor footer + docs/main/ai-design.md § "What we don't claim".
- **No real-time learning** - model weights are tuned by admin, not auto-learned from outcomes.
- **OpenAI dependency** - system relies on `gpt-4o-mini`. If OpenAI is down, scoring fails (graceful - score row marked `status='failed'`, UI shows retry).
- **Single-region deployment** - Vercel + Railway in their default regions; no multi-region failover for the sprint.

## SQL Cheat Sheet (paste into Supabase SQL editor during demo)

```sql
-- Show all match scores with weights snapshot
SELECT m.overall_score, m.band, m.weights_used, m.prompt_version, m.model_used,
       p.full_name AS candidate, j.title AS job
FROM match_scores m
JOIN profiles p ON p.id = m.candidate_id
JOIN jobs j ON j.id = m.job_id
ORDER BY m.created_at DESC LIMIT 10;

-- Show bias flag overrides with recruiter justification
SELECT b.term, b.category, b.override_reason, p.full_name AS recruiter, b.overridden_at
FROM bias_flags b
JOIN profiles p ON p.id = b.overridden_by
WHERE b.status = 'overridden'
ORDER BY b.overridden_at DESC;

-- Show audit trail for a single application end-to-end
SELECT action, actor_type, created_at, details
FROM audit_logs
WHERE entity_type IN ('application', 'match_score')
  AND entity_id IN ('<app_id>', '<match_score_id>')
ORDER BY created_at;
````
