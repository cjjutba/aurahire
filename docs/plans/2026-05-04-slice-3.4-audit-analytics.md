# Slice 3.4 - Audit Log + System Analytics Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (in the executing session) to implement this plan task-by-task. Dispatch a fresh subagent per task; review between tasks; halt on failure. **This slice ships two related but independent surfaces.** The audit log is the system's immutable record-keeping - every consequential action across all prior slices accumulates here, and this is where examiners verify that the system _actually_ writes to `audit_logs` like the docs claim. The analytics page is the visual story - KPI tiles + six Recharts visualizations that demonstrate the system has volume, velocity, and shape. Together they're the "look at all the events flowing through" half of the admin portal.

**Goal:** Ship `/admin/audit` (replacing the stub) and `/admin/analytics` (replacing the stub) - the two read-only oversight surfaces. Backend gets two new sub-controller / service / repository sets under existing `AdminModule` (from 3.1). Five endpoints total: `GET /admin/audit` (paginated, filterable list), `GET /admin/audit/:id` (single entry detail for the drawer), `GET /admin/audit/export.csv` (filtered CSV stream), `GET /admin/analytics` (cached 5-min KPI + 6-chart bundle), `GET /admin/analytics/export.csv` (per-chart CSV - wired to the chart actions). Frontend gets `/admin/audit` table with filter bar + diff drawer reusing 3.2's `<RawOutputJsonViewer>`, and `/admin/analytics` with KPI tiles + Recharts visualizations (LineChart, BarChart, AreaChart). New project dep: `recharts ^2.13` (pinned in tech-stack.md, not yet installed). By end of this slice: an admin can filter the audit log down to "all actions Maria performed last week," click a row, see the full JSON diff that was persisted, and export the filtered slice as CSV - AND can switch to /analytics and see user growth, job postings over time, and the application-status stacked area chart rendering with real data.

**Architecture:** Two independent sub-controllers in the existing AdminModule - no cross-dependencies between Audit and Analytics services. Audit reads `audit_logs` directly (already populated by every prior slice's mutations); Analytics composes aggregations across `profiles`, `jobs`, `applications`, `match_scores`, `resumes`, `audit_logs` via Drizzle group-by queries. **Both surfaces are read-only.** Analytics endpoint is cached 5 minutes (admin lookup cadence is bursty; data changes slowly relative to TTL). CSV export streams via `@nestjs/common`'s `StreamableFile` - for sprint, the dataset is small enough that materializing in memory is fine; we'll buffer-then-send. Recharts is added to `apps/web/package.json` as a project-scoped install (no global system change).

**Tech Stack:** NestJS sub-controllers in existing `AdminModule`, Drizzle aggregations (groupBy + date_trunc for time series), `@nestjs/cache-manager` for analytics 5-min TTL, no AI calls anywhere, **Recharts ^2.13** for charts (added in Task 1 via `pnpm add`), reused `<RawOutputJsonViewer>` from 3.2 for the audit detail drawer.

**Sprint reference:** `docs/main/sprint-plan.md` § Day 3 → Slice 3.4

**Estimated wall time:** 75 min (executing agent) + ~10 min (human verification with chart spot-checks)

**Depends on:** All prior Day 1 + Day 2 + Slices 3.1 + 3.2 + 3.3 committed. Specifically:

- 3.3: AdminModule has 4 sub-controllers (stats / users / jobs / applications / config); 3.4 adds the 5th and 6th
- 3.2: `<RawOutputJsonViewer>` reused for audit detail drawer
- 3.1: AdminModule sub-controller pattern + `<Sheet>` / `<Dialog>` primitives
- 2.6 + 2.7: `match_scores` + `bias_flags` populated → analytics has real data
- All slices: `audit_logs` rows accumulated since Day 1 → audit table has real entries

**The system MUST have accumulated reasonable audit/score/job volume** for the analytics demo to be visually meaningful. By end of Day 2 + 3.1 there should be 30+ audit rows, 5+ jobs, 1+ application - enough for the charts to look populated.

## Notes from prior slices' execution (read before starting)

- **Hook naming:** orval emits as `useAdminAuditControllerListV1`, `useAdminAuditControllerGetByIdV1`, `useAdminAnalyticsControllerOverviewV1`. The CSV export endpoint generates a hook too but is unused - frontend uses an anchor `<a>` with a Bearer header via fetch-then-blob trick (see Task 11 Step 2).
- **OpenAI SDK v6.35:** zero AI calls in this slice. All reads/aggregations.
- **`HttpExceptionFilter` preserves extra fields** (2.7 fix). Useful for the `EXPORT_TOO_LARGE` 413 with `{ code, message, rowCount }`.
- **`@nestjs/throttler` not registered:** no throttling; the export endpoint is the most expensive but capped at 10k rows.
- **`<RawOutputJsonViewer>` from 3.2** at `apps/web/components/admin/raw-output-json-viewer.tsx` - reused as-is for the audit detail drawer.
- **`<Sheet>`, `<Dialog>`, `<DropdownMenu>` shadcn-style primitives all exist** (added across 2.7 + 3.1). No new UI primitives required for THIS slice's work.
- **Recharts is NOT yet installed** - Task 1 adds it. Pinned to `^2.13` per `docs/main/tech-stack.md`. The package is React 18-compatible (the project uses React 19; `recharts` 2.13+ supports React 19).
- **The audit_logs `details` field is `jsonb` with default `{}`** (schema line 486). Always present - never null. Frontend can safely render it via JSON.stringify.
- **The `audit_logs` table has indexes** on `created_at`, `(actor_id, created_at)`, `(entity_type, entity_id)`, `action` (per schema lines 491-495). All filter combinations in this slice hit indexes.
- **Date-trunc time series:** Postgres' `date_trunc('day', col)` returns timestamps; we want ISO date strings in the response. Cast in SQL: `to_char(date_trunc('day', col), 'YYYY-MM-DD') AS date`.
- **Analytics computation cost:** with sprint volume (~50 audit rows, ~5 jobs, ~1-3 applications, ~3-5 users) all queries return in < 100ms. The 5-min cache is sized for production where queries get heavier; in dev it's mostly a no-op but kept for parity.

```ts
import { AUDIT_ACTOR_TYPE } from "../enums";

// ---------- LIST ADMIN AUDIT QUERY ----------

export const listAdminAuditQuerySchema = z.object({
  actorId: uuidSchema.optional(),
  q: z.string().max(200).optional(), // searches actor full_name + email
  entityType: z
    .enum([
      "profile",
      "job",
      "application",
      "match_score",
      "profile_score",
      "bias_flag",
      "scoring_config",
      "resume",
    ])
    .optional(),
  action: z.string().max(100).optional(), // exact-match or prefix-match (server decides; sprint = ilike '%action%')
  actorType: z.enum(AUDIT_ACTOR_TYPE).optional(),
  dateFrom: z.string().datetime().optional(),
  dateTo: z.string().datetime().optional(),
  page: z.coerce.number().int().min(1).default(1),
  limit: z.coerce.number().int().min(1).max(100).default(50),
});
export type ListAdminAuditQuery = z.infer<typeof listAdminAuditQuerySchema>;

// ---------- ANALYTICS QUERY ----------

export const analyticsQuerySchema = z
  .object({
    dateFrom: z.string().datetime().optional(),
    dateTo: z.string().datetime().optional(),
  })
  .refine(
    (data) => {
      if (!data.dateFrom || !data.dateTo) return true;
      return new Date(data.dateFrom) <= new Date(data.dateTo);
    },
    { message: "dateFrom must be ≤ dateTo", path: ["dateFrom"] },
  );
export type AnalyticsQuery = z.infer<typeof analyticsQuerySchema>;
```

**Note:** `AUDIT_ACTOR_TYPE` is already exported from the shared enums (per Slice 1.3). Import path matches existing usage.

```ts
      );
```

```ts
        and(
          eq(resumesTable.parseStatus, "parsed"),
          gte(resumesTable.createdAt, from),
          lte(resumesTable.createdAt, to),
        ),

    const scoreRows = await this.db
      .select({
        date: sql<string>`to_char(date_trunc('day', ${matchScoresTable.createdAt}), 'YYYY-MM-DD')`,
        avg: sql<number | null>`avg(${matchScoresTable.latencyMs})::float`,
      })

      .where(
        and(
          gte(matchScoresTable.createdAt, from),
          lte(matchScoresTable.createdAt, to),
        ),
      )
      .groupBy(sql`date_trunc('day', ${matchScoresTable.createdAt})`);

    // Merge by date
    const byDate = new Map<
      string,
      { avgParseMs: number; avgScoreMs: number }
    >();
    for (const r of parseRows) {
      byDate.set(r.date, {
        avgParseMs: Math.round(r.avg ?? 0),
        avgScoreMs: 0,
      });
    }
    for (const r of scoreRows) {
      const existing = byDate.get(r.date) ?? { avgParseMs: 0, avgScoreMs: 0 };
      byDate.set(r.date, {
        ...existing,
        avgScoreMs: Math.round(r.avg ?? 0),
      });
    }

    return Array.from(byDate.entries())
      .map(([date, vals]) => ({ date, ...vals }))
      .sort((a, b) => a.date.localeCompare(b.date));
  }

  async topRecruiters(limit: number): Promise<
    Array<{
      recruiterId: string;
      fullName: string;
      jobCount: number;

    }>
  > {

        fullName: profilesTable.fullName,

      .leftJoin(applicationsTable, eq(applicationsTable.jobId, jobsTable.id))
      .where(eq(profilesTable.role, "recruiter"))
      .groupBy(profilesTable.id, profilesTable.fullName)
      .orderBy(desc(sql<number>`count(distinct ${jobsTable.id})`))
      .limit(limit);
    return rows;
  }
}
```

```ts
    const cached = await this.cache.get<AnalyticsBundleDto>(cacheKey);
    if (cached) return cached;

    const periodMs = to.getTime() - from.getTime();
    const periodDays = Math.max(1, periodMs / DAY_MS);

    // KPIs

    ]);

      priorTotal > 0
        ? Math.round((newUsersThisPeriod / priorTotal) * 1000) / 10
        : 0;

      Math.round((apsInPeriod / periodDays) * 10) / 10;

        this.repo.applicationsByDay(from, to),
        this.repo.scoreDistribution(from, to),
        this.repo.aiProcessingTimeByDay(from, to),
        this.repo.topRecruiters(10),
      ]);

    const charts: AnalyticsChartsDto = {
      userGrowth: this.pivotByRole(userGrowthRows),
      jobsOverTime: this.pivotByJobStatus(jobsRows),
      applicationsByStatus: this.pivotByApplicationStatus(appsRows),
      scoreDistribution: this.fillBuckets(scoreDist),
      aiProcessingTime: aiProc,
      topRecruiters: topRec,
    };

    const bundle: AnalyticsBundleDto = {
      range: { from: from.toISOString(), to: to.toISOString() },
      kpis,
      charts,
    };

    await this.cache.set(cacheKey, bundle, CACHE_TTL_MS);
    return bundle;
  }

  // -----------------------------------------------------------------
  // PRIVATE - pivots from "long" SQL output to "wide" chart shape
  // -----------------------------------------------------------------

  private pivotByRole(
    rows: Array<{ date: string; role: string; count: number }>,
  ): Array<{
    date: string;
    candidate: number;
    recruiter: number;
    admin: number;
  }> {
    const byDate = new Map<
      string,
      { candidate: number; recruiter: number; admin: number }
    >();
    for (const r of rows) {
      const entry = byDate.get(r.date) ?? {
        candidate: 0,
        recruiter: 0,
        admin: 0,
      };
      if (r.role === "candidate") entry.candidate = r.count;
      else if (r.role === "recruiter") entry.recruiter = r.count;
      else if (r.role === "admin") entry.admin = r.count;
      byDate.set(r.date, entry);
    }
    return Array.from(byDate.entries())
      .map(([date, v]) => ({ date, ...v }))
      .sort((a, b) => a.date.localeCompare(b.date));
  }

  private pivotByJobStatus(
    rows: Array<{ date: string; status: string; count: number }>,
  ): Array<{
    date: string;
    draft: number;
    published: number;
    archived: number;
  }> {
    const byDate = new Map<
      string,
      { draft: number; published: number; archived: number }
    >();
    for (const r of rows) {
      const entry = byDate.get(r.date) ?? {
        draft: 0,
        published: 0,
        archived: 0,
      };
      if (r.status === "draft") entry.draft = r.count;
      else if (r.status === "published") entry.published = r.count;
      else if (r.status === "archived") entry.archived = r.count;
      byDate.set(r.date, entry);
    }
    return Array.from(byDate.entries())
      .map(([date, v]) => ({ date, ...v }))
      .sort((a, b) => a.date.localeCompare(b.date));
  }

  private pivotByApplicationStatus(
    rows: Array<{ date: string; status: string; count: number }>,
  ): Array<{
    date: string;
    applied: number;
    screening: number;
    interview: number;
    offer: number;
    hired: number;
    rejected: number;
    withdrawn: number;
  }> {
    const STATUSES = [
      "applied",
      "screening",
      "interview",
      "offer",
      "hired",
      "rejected",
      "withdrawn",
    ] as const;
    const empty = () =>
      Object.fromEntries(STATUSES.map((s) => [s, 0])) as Record<
        (typeof STATUSES)[number],
        number
      >;
    const byDate = new Map<string, ReturnType<typeof empty>>();
    for (const r of rows) {
      const entry = byDate.get(r.date) ?? empty();
      if ((STATUSES as readonly string[]).includes(r.status)) {
        entry[r.status as (typeof STATUSES)[number]] = r.count;
      }
      byDate.set(r.date, entry);
    }
    return Array.from(byDate.entries())
      .map(([date, v]) => ({ date, ...v }))
      .sort((a, b) => a.date.localeCompare(b.date));
  }

  private fillBuckets(
    rows: Array<{ bucket: string; count: number }>,
  ): Array<{ bucket: string; count: number }> {
    const order = [
      "0-9",
      "10-19",
      "20-29",
      "30-39",
      "40-49",
      "50-59",
      "60-69",
      "70-79",
      "80-89",
      "90-100",
    ];
    const map = new Map(rows.map((r) => [r.bucket, r.count]));
    return order.map((b) => ({ bucket: b, count: map.get(b) ?? 0 }));
  }
}
```

```tsx
import { useState } from "react";
import { toast } from "sonner";
import { Download } from "lucide-react";
import { Button } from "@/components/ui/button";
import { createSupabaseBrowserClient } from "@/lib/auth/client";

interface Props {
  currentParams: string; // already-stringified URLSearchParams (excluding page/limit)
}

export function ExportButtonClient({ currentParams }: Props) {
  const [working, setWorking] = useState(false);

  async function download() {
    setWorking(true);
    try {
      const supabase = createSupabaseBrowserClient();
      const {
        data: { session },
      } = await supabase.auth.getSession();
      if (!session) {
        toast.error("Please sign in");
        return;
      }
      const apiUrl = process.env.NEXT_PUBLIC_API_URL ?? "http://localhost:3333";

      // Strip pagination params from the export query (export is unpaginated)
      const params = new URLSearchParams(currentParams);
      params.delete("page");
      params.delete("limit");

      const res = await fetch(
        `${apiUrl}/api/v1/admin/audit/export.csv?${params.toString()}`,
        {
          headers: { Authorization: `Bearer ${session.access_token}` },
        },
      );

      if (res.status === 413) {
        toast.error("Export too large", {
          description: "Narrow filters and try again.",
        });
        return;
      }
      if (!res.ok) {
        toast.error("Export failed", { description: `HTTP ${res.status}` });
        return;
      }

      // Extract filename from Content-Disposition
      const cd = res.headers.get("content-disposition") ?? "";
      const match = /filename="?([^";]+)"?/i.exec(cd);
      const filename =
        match?.[1] ??
        `audit-export-${new Date().toISOString().slice(0, 10)}.csv`;

      const blob = await res.blob();
      const url = URL.createObjectURL(blob);
      const a = document.createElement("a");
      a.href = url;
      a.download = filename;
      document.body.appendChild(a);
      a.click();
      a.remove();
      URL.revokeObjectURL(url);
      toast.success("Export downloaded");
    } finally {
      setWorking(false);
    }
  }

  return (
    <Button
      onClick={download}
      disabled={working}
      variant="outline"
      className="rounded-[var(--radius-pill)]"
    >
      <Download className="mr-1 h-3 w-3" />
      {working ? "Exporting..." : "Export CSV"}
    </Button>
  );
}
```

```tsx
"use client";

import { useRouter, useSearchParams } from "next/navigation";
import { useState, useTransition } from "react";
import { Input } from "@/components/ui/input";
import { Button } from "@/components/ui/button";

const DAY_MS = 24 * 60 * 60 * 1000;

interface Props {
  initialFrom?: string;
  initialTo?: string;
}

function isoDay(d: Date): string {
  return d.toISOString().slice(0, 10);
}

export function DateRangeClient({ initialFrom, initialTo }: Props) {
  const router = useRouter();
  const sp = useSearchParams();
  const [isPending, startTransition] = useTransition();
  const [from, setFrom] = useState(initialFrom ? initialFrom.slice(0, 10) : "");
  const [to, setTo] = useState(initialTo ? initialTo.slice(0, 10) : "");

  function applyPreset(days: number) {
    const newTo = new Date();
    const newFrom = new Date(newTo.getTime() - days * DAY_MS);
    apply(isoDay(newFrom), isoDay(newTo));
  }

  function applyCustom() {
    if (!from || !to) return;
    apply(from, to);
  }

  function apply(fromIso: string, toIso: string) {
    const next = new URLSearchParams(sp.toString());
    next.set("dateFrom", new Date(fromIso).toISOString());
    next.set("dateTo", new Date(toIso + "T23:59:59").toISOString());
    setFrom(fromIso);
    setTo(toIso);
    startTransition(() => router.push(`?${next.toString()}`));
  }

  return (
    <div className="flex flex-wrap items-end gap-2">
      <div className="flex gap-1">
        {[7, 30, 90].map((d) => (
          <Button
            key={d}
            onClick={() => applyPreset(d)}
            disabled={isPending}
            variant="outline"
            className="rounded-[var(--radius-pill)] text-xs"
          >
            Last {d}
          </Button>
        ))}
      </div>
      <div className="flex items-end gap-2">
        <div>
          <label className="mb-1 block text-xs uppercase text-[var(--color-muted)]">
            From
          </label>
          <Input
            type="date"
            value={from}
            onChange={(e) => setFrom(e.target.value)}
            className="text-xs"
          />
        </div>
        <div>
          <label className="mb-1 block text-xs uppercase text-[var(--color-muted)]">
            To
          </label>
          <Input
            type="date"
            value={to}
            onChange={(e) => setTo(e.target.value)}
            className="text-xs"
          />
        </div>
        <Button
          onClick={applyCustom}
          disabled={!from || !to || isPending}
          className="rounded-[var(--radius-pill)] bg-[var(--color-primary)] text-xs"
        >
          Apply
        </Button>
      </div>
    </div>
  );
}
```

## Why This Slice Matters

The audit log is the system's _receipts_. Every prior slice has been writing to `audit_logs` - registrations, job creations, applications, AI scores, status changes, bias overrides, config changes. Until this slice, those rows existed only as DB rows queryable via Supabase MCP. This slice makes them browsable, filterable, and exportable for thesis-defense purposes.

The analytics page is the system's _vital signs_. KPI tiles + 6 Recharts visualizations turn database aggregations into a story:

- **The AI is actually running** - the AI Processing Time chart shows real parse + score latencies trending over days
- **The system has volume** - even with a sparse demo, User Growth + Jobs Over Time show real user/job creation events
- **The funnel is shaped like a funnel** - Applications by Status stacked area shows applied → screening → interview → offer
- **Scores aren't all the same** - Score Distribution histogram demonstrates real variance, validating that the AI is differentiating candidates

Two design choices worth defending:

1. **Audit endpoints are NOT cached.** Admins inspecting audit logs need always-fresh data - they might be investigating an incident that happened seconds ago.

2. **CSV export caps at 10,000 rows with a 413 response, not silent truncation.** Sprint scale won't hit this, but it's the right contract - silent truncation would mislead an examiner querying historical data.

This slice is the "look at all the events flowing through" half of the admin portal. The next slice (3.5 Bias & Fairness Monitor) is the "look at the fairness story specifically" half - it composes from `bias_flags` + score distributions and is mostly chart work building on top of the patterns established here.
